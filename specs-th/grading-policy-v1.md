# นโยบายการให้คะแนน (Grading Policy)

> แปลจาก `specs/grading-policy-v1.md` ถ้าความหมายไม่ตรงกัน ให้ยึดต้นฉบับภาษาอังกฤษ

## จำนวนครั้งที่ส่งตรวจได้ (Submission limit)

- นักศึกษาแต่ละคนส่งตรวจอย่างเป็นทางการ (official grading) ได้ **ไม่เกิน 10 ครั้ง**
- การรันเทสและ Docker build บนเครื่องตัวเอง **ไม่จำกัดจำนวน**
- ส่ง repo และ commit **เดิม** ซ้ำ จะได้ผลเดิมกลับมา โดย **ไม่เสียสิทธิ์** เพิ่ม
- ความขัดข้องของระบบฝั่งผู้สอน **ไม่เสียสิทธิ์**
- ความล้มเหลวจากงานของนักศึกษา **เสียสิทธิ์** ได้แก่ official tests ไม่ผ่านหรือหมดเวลา, Docker build ไม่ผ่าน และ bot ของนักศึกษาไม่ตอบ
- เฉพาะผลเทสที่รันจบและถูกบันทึกแล้วเท่านั้น ที่นับเป็นคะแนน CI

## การลงทะเบียนและคำสั่ง Webex (Registration and Webex commands)

**IPA2026** คือห้องสำหรับนักศึกษาทดสอบด้วยมือ ในห้องนี้ให้ใช้เฉพาะ router ที่ได้รับมอบหมายในช่วง `10.0.29.102`–`10.0.29.105`

router `10.0.29.101` **สงวนไว้สำหรับ Live grading อย่างเป็นทางการ** ในห้อง **IPA2026 Exam Room** **ห้ามส่ง YAML ทดสอบเองในห้องสอบ**

bot ของนักศึกษาต้องรับ mention ได้ **ทั้งสองห้อง** และตอบกลับในห้องที่คำขอนั้นส่งมา

- ใช้บัญชี Webex ที่อีเมลเป็น `student-id@kmitl.ac.th`
- เพิ่ม bot ของนักศึกษา **หนึ่งตัว** ที่มี **ชื่อแสดงตรงกับรหัสนักศึกษา 8 หลักเป๊ะ ๆ** เข้าทั้งห้อง IPA2026 และ IPA2026 Exam Room
- เปิด webhook และ tunnel ไว้ให้ใช้งานได้ในทั้งสองห้องสำหรับการตรวจ
- วางโปรเจกต์และ `compose.yaml` ไว้ที่ **root ของ repository**
- ทำให้ branch `main` **ผู้สอนอ่านได้** (ถ้า repo เป็น private ต้องให้สิทธิ์ผู้สอน)

ในห้อง IPA2026 Exam Room ให้ **เลือก @mention ของ bot `IPA2026-Reference` จากรายการที่ Webex แนะนำจริง ๆ** แล้วพิมพ์คำสั่งใดคำสั่งหนึ่งต่อไปนี้ การพิมพ์ชื่อ bot เป็นข้อความธรรมดา **ไม่ถือเป็น mention** และนักศึกษา **ไม่ต้องใส่รหัสนักศึกษา** ในคำสั่งเหล่านี้

- **`register https://github.com/owner/repository`**: บันทึก repository และค้นหา bot ในห้องที่มีชื่อแสดงตรงกับรหัสของนักศึกษา **เพียงตัวเดียว**
- **`verify`**: ตรวจการลงทะเบียน, SHA ล่าสุดของ `main` ที่อ่านได้, Student CI ที่ผ่านสำหรับ SHA นั้นพอดี และคำตอบ smoke 2 ข้อจาก bot ที่ลงทะเบียนในห้องสอบ ได้แก่
  - `no_yaml` เมื่อไม่แนบไฟล์
  - `invalid_version` เมื่อแนบ YAML ที่ version ไม่ถูกต้อง (YAML นี้เปลี่ยน router ไม่ได้)

  คำสั่งนี้ **ไม่บังคับ ฟรี** ไม่เริ่ม GitHub Actions และไม่ใช้สิทธิ์ส่งตรวจ ถ้าสั่งซ้ำต้องรอ **30 วินาที** ถ้า Student CI ยังไม่ผ่าน จะข้าม live smoke และถ้ามีคำสั่ง Webex อื่นรออยู่ verify จะหลีกทางทันทีเพื่อไม่ให้ขวางคิว
- **`grade`**: ตรวจ SHA ล่าสุดของ `main` ด้วย official CI/build แล้วตามด้วย Live **เฉพาะเมื่อ build สำเร็จและ official tests รันจบ**
- **`score`**: แสดงคะแนน Take-home ที่ดีที่สุดเต็ม 20, ผลล่าสุด และจำนวนสิทธิ์ที่ใช้ไป/เหลือ คำสั่งนี้ **ฟรี** งานที่อยู่ในคิวจะแสดงลำดับคิวปัจจุบันด้วย

ผู้สอนอาจใช้คำสั่ง `queue` ในห้อง IPA2026 Exam Room เพื่อดูรหัสนักศึกษาและหมายเลขงานที่กำลังรัน CI หรือ Live อยู่ รวมถึงงานที่รอในแต่ละคิว คำสั่งนี้ไม่ใช้สิทธิ์ส่งตรวจ

## CI: 10 คะแนน

public tests และ hidden tests รวมกันในแต่ละ Part:

- Part 1: 2 คะแนน
- Part 2: 2 คะแนน
- Part 3: 4 คะแนน
- Part 4: 2 คะแนน

สำหรับแต่ละ Part:

    คะแนน = จำนวนเทสที่ผ่าน / จำนวนเทสทั้งหมดใน Part นั้น * น้ำหนักของ Part

- **Student CI** รัน public tests, build webhook image และทำ HTTP smoke check แบบ offline ภายใน image
- **การตรวจอย่างเป็นทางการของผู้สอน** รัน hidden tests เพิ่ม และทำ image smoke check ของตัวเอง
- **ไม่ต้อง** publish image ขึ้น Docker Hub

เรื่องคิวและเวลา:

- ตัวจัดคิวการตรวจรัน official CI ได้พร้อมกัน **สูงสุด 4 งาน**
- Live test ยังคงตรวจ **ทีละคน** เพื่อไม่ให้การเปลี่ยน router และการตอบ Webex ทับกัน
- งานที่ถูกรับเข้าระบบทั้งหมดยังอยู่ในฐานข้อมูลการตรวจระหว่างรอ อยู่ในคิวแล้ว **ไม่ต้องส่งใหม่**
- official CI job มีเวลาจำกัด **5 นาที** official tests หยุดที่ **2 นาที** และ Docker build หยุดที่ **90 วินาที**
- ถ้าโค้ดของนักศึกษาทำให้หมดเวลา ถือเป็นการส่งที่ถูกให้คะแนนแล้ว (เสียสิทธิ์) และ **ข้าม Live**
- ความล้มเหลวของบริการตรวจหรือ GitHub **คืนสิทธิ์**

## Live: 10 คะแนน

- ผู้สอนมีชุด input สำหรับ Live **58 แบบ**
- การส่งตรวจแต่ละครั้งได้ **20 กรณีพอดี** น้ำหนักเท่ากัน **กรณีละ 0.5 คะแนน** โดยเลือก **หนึ่งกรณีจากแต่ละกลุ่มความสามารถที่บังคับ**
- การเลือกนี้ทำซ้ำได้เหมือนเดิมสำหรับการส่งครั้งนั้น และเก็บ ID ของกรณีที่เลือกไว้พร้อมผลตรวจ
- วิธีนี้ทำให้ความครอบคลุมเทียบกันได้ แต่ค่าและรูปแบบ YAML จะเปลี่ยนไปในแต่ละครั้งที่ส่ง

เงื่อนไข:

- ต้องผ่านการตรวจ official build **ก่อน** จึงจะเริ่ม Live
- ถ้า build หรือ image smoke ไม่ผ่าน **เก็บคะแนน CI ที่ได้ไว้** และได้คะแนน Live **0**
- ถ้า bot ที่ลงทะเบียนไม่ตอบคำขอ Live ภายในเวลาที่กำหนด **กรณีที่เหลือทั้งหมดถือว่าไม่ผ่านทันที** เพื่อให้คนถัดไปเริ่มได้ กรณีนี้ **เสียสิทธิ์**
- ความล้มเหลวของบริการตรวจ, Webex API หรือ router **คืนสิทธิ์**

Live ครอบคลุม:

- การตรวจ YAML
- status แบบ found / not_found
- plan แบบ create / no_change / update
- apply พร้อมการตรวจสถานะ router แยกอิสระ
- delete / delete ซ้ำ
- operation ที่รองรับของ RESTCONF, NETCONF, Ansible และ Netmiko/TextFSM

การเริ่ม `grade` ถือว่า **อนุญาตให้ระบบตรวจลบและสร้างใหม่เฉพาะ `Loopback<student-id>` บน router `10.0.29.101`** ระบบจะลบ interface นั้น **ก่อน** Live แม้การทดสอบด้วยมือจะทิ้งไว้ด้วย description อื่น และลบ **อีกครั้งหลัง** Live interface ชื่ออื่นจะไม่ถูกลบเด็ดขาด ข้อความตอบรับ grade ก็จะแจ้งนักศึกษาเรื่องการรีเซ็ตนี้ด้วย

IP /32 ของ Live อย่างเป็นทางการมาจากช่วง **`192.0.2.128/27`**
- นักศึกษา **ห้ามใช้ช่วงนี้** สำหรับ configuration ที่ทดลองเอง
- แต่ bot ของนักศึกษา **ยังต้องรับ** คำขอ Live จากผู้ตรวจที่ใช้ช่วงนี้ได้

อื่น ๆ:

- deploy bot ด้วย **Docker Compose** และเปิดไว้ให้พร้อมตรวจ
- ผู้สอนทดสอบผ่าน Webex mention และไฟล์ YAML ที่แนบ
- คำขอ Live และ JSON ที่ตอบกลับจะ **มองเห็นได้** ในห้อง IPA2026 Exam Room
- การสุ่มเลือก **ไม่ได้ซ่อน** ไฟล์ YAML ที่แนบจากสมาชิกคนอื่นในห้องสอบ
- **ไม่ต้องส่ง** screenshot, output ของคำสั่ง Docker หรือ log ของ live ที่ทำด้วยมือ

## คะแนนสุดท้าย (Final score)

- ข้อสอบปลายภาคใช้ **CI 10 + Live 10 + MCQ 10 = 30 คะแนน**
- MCQ เป็นการประเมินแยก เก็บนอกระบบตรวจนี้
- ระหว่างสอบ MCQ เอกสารอ้างอิงที่อนุญาตมี **เพียง repository IPA2026-student-starter** เท่านั้น รวมถึง README, specs, โค้ด และ public tests ในนั้น
- bot ตรวจงานและ SQLite รายงานเฉพาะผล Take-home CI + Live เต็ม 20
- ผู้สอนจะรวมคะแนน MCQ กับคะแนน Take-home นอกระบบนี้
- ใช้คะแนน Take-home รวมที่ **สูงสุดจากการส่งตรวจที่ถูกต้องครั้งเดียว** ที่ส่งก่อนกำหนดเวลา
- **ห้ามรวม** คะแนน CI และ Live ที่มาจากการส่งคนละครั้ง
- งานที่ถูกรับก่อนกำหนดเวลาจะถูกตรวจจนเสร็จ
- เก็บ repository, commit SHA, ผลตรวจ และคะแนนของทุกการส่ง

## การตอบกลับของ Bot (Bot feedback)

- **เมื่อรับงาน**: แจ้งจำนวนครั้งที่ใช้, จำนวนครั้งที่เหลือ และคะแนนดีที่สุดก่อนหน้า
- **หลังตรวจเสร็จ**: แจ้งคะแนน CI, คะแนน Live, คะแนน Take-home, คะแนน Take-home ที่ดีที่สุด, จำนวนครั้งที่ใช้ และจำนวนครั้งที่เหลือ
- การถามคะแนน (`score`) **ไม่ใช้สิทธิ์**
